# Parent project review

Baseline: `7d5a5d1`. Review date: 21 September 2026.

## Corrected behavior

- Identical simultaneous payment requests now resolve to one persisted transaction. Only the insert winner attempts normal publication.
- Reusing a transaction reference with a different merchant, amount or payment status returns 409 without returning the original transaction.
- Amounts with fractional minor units are rejected before storage instead of being rounded by PostgreSQL.
- Inactive merchants cannot accept new payments. Identical retries still resolve historical accepted payments.
- PostgreSQL mapping converts only the numeric amount column. Numeric-looking merchant names and firmware versions retain their string values.
- Production startup rejects implicit development and example secrets, invalid encryption keys and example database URLs.
- The Security workflow's unavailable `aquasecurity/trivy-action@0.33.1` reference is replaced by the verified v0.36.0 commit. The HIGH/CRITICAL failure gates are unchanged.
- CI now runs real PostgreSQL regression tests as well as HTTP tests using the memory repository.
- The restored scanner exposed unrestricted HTTPS egress in Terraform. The security group now uses an explicit destination allowlist with no default outbound access. Deployment requires reviewed endpoint ranges before bootstrap can succeed.

## Verification

Local lint and TypeScript compilation passed. The complete suite passed 43 tests, including two real PostgreSQL tests. The concurrent database test sends 20 identical requests, verifies one 201 response and 19 original-identity responses, checks one stored row and one publisher invocation, then verifies a conflicting retry is rejected.

The local database used a dedicated `soundbox_test` database on loopback port 55534 and a unique retained schema. Publisher calls are mocked in these regression tests. They do not constitute a new MQTT delivery or device acknowledgment test. Docker was unavailable during this review, so no local container build or image scan is claimed.

`npm audit` reported nine moderate findings and no high or critical findings. Suggested fixes include major upgrades of the optional Google Pub/Sub dependency and Vitest. These remain a separate dependency maintenance item; they are not suppressed by this change.

## Remaining design limits

The parent platform still publishes directly after database persistence. A process crash or broker problem can leave a stored payment without publication. It has no automatic durable outbox recovery or device acknowledgment protocol. MQTT QoS 1 can deliver duplicates, and the text simulator does not establish exactly-once audio. Management JWTs remain global administrative credentials, not merchant-specific membership grants. Production MQTT accounts, ACLs and TLS remain roadmap work.

[PayOps GenAI](https://github.com/sakti69-cssoft/PayOps) is the child project for durable dispatch, signed receipts, monitoring and incident investigation. Its verified capabilities must not be attributed to this parent implementation without an explicit integration.
